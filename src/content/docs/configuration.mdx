Nimbus 在 `astro.config.ts` 中配置。`@cloudflare/nimbus-docs` 导出的 `defineConfig` 用于定义站点配置，为了不与 Astro 自己的 `defineConfig` 冲突，通常重命名为 `defineNimbusConfig`。`nimbus()` 集成接收这份配置，以及构建选项。

```ts title="astro.config.ts"
import { defineConfig } from "astro/config";
import nimbus, {
  defineConfig as defineNimbusConfig,
} from "@cloudflare/nimbus-docs";

const config = defineNimbusConfig({
  site: "https://docs.example.com",
  title: "Acme",
  description: "使用 Acme 构建产品。",
  locale: "zh-CN",
  github: "https://github.com/acme/docs",
  sidebar: {
    items: ["index", { autogenerate: { collection: "docs" } }],
  },
});

export default defineConfig({
  integrations: [nimbus(config)],
});
```

## 站点信息

| 字段 | 类型 | 说明 |
|---|---|---|
| `site` | string | **必填。** 站点的正式地址，会同步给 Astro 的 `site`。 |
| `title` | string | **必填。** 站点标题，也是元数据的兜底标题。 |
| `description` | string | 默认的 meta 描述。 |
| `locale` | string | 文档语言，例如 `"zh-CN"` 或 `"en"`。它会写入 `<html lang>`。 |
| `homeLabel` | string | 面包屑中“首页”的文案。 |
| `github` | string \| null | 页头 GitHub 链接；设为 `null` 可以隐藏。 |
| `editPattern` | string \| null | “编辑此页”的链接模板，`{path}` 会替换成页面路径。 |
| `socialImage` | string | 默认的社交卡片图片。 |
| `sidebar` | object | 侧边栏配置，见下一节。 |
| `search` | object \| `false` | 搜索后端；设为 `false` 可以关闭搜索。 |
| `head` | array | 全站注入 `<head>` 的元素。 |

<Aside type="caution" title="上线前务必修改 site">
  `site` 会决定 canonical URL、社交卡片的绝对地址、`robots.txt`、sitemap 以及 `/llms.txt` 中的链接。保留示例地址会让这些输出都指向错误的位置。
</Aside>

## 侧边栏

默认情况下，侧边栏镜像 `src/content/docs/` 的目录结构。文件夹会变成分组，文件夹里的 `index.mdx` 是该分组的落地页，可以在它的 frontmatter 中通过 `sidebar.group.label` 重命名分组。

```mdx title="src/content/docs/guides/index.mdx"
---
title: 指南
sidebar:
  group:
    label: 使用指南
---
```

在分组内：

- `sidebar.order` 控制排序，数字越小越靠前。
- `sidebar.label` 可以缩短页面在侧边栏中的标题。
- `sidebar.hidden: true` 会构建页面，但不把它列在导航中。

需要调整顶层顺序或加入外部链接时，在 `astro.config.ts` 中设置 `sidebar.items`：

```ts title="astro.config.ts"
sidebar: {
  items: [
    "index",
    { label: "指南", autogenerate: { directory: "guides" } },
    { label: "GitHub", link: "https://github.com/cloudflare/nimbus" },
  ],
},
```

列表中出现的项会替换自动生成的顶层结构，项上设置的 `label` 优先于文件夹自身的 `sidebar.group.label`。

## 搜索

Nimbus 默认使用 [Pagefind](https://pagefind.app/)。搜索索引在构建时生成，因此开发服务器里搜索可能不可用：

```sh
bun run build
bun run preview
```

打开预览地址后再试搜索，就能查到构建后的内容。需要关闭搜索时设置 `search: false`。

## 内容校验

校验规则按需开启。脚手架默认启用了两条最关键的规则：frontmatter 结构，以及内部链接。

```ts title="astro.config.ts"
nimbus(config, {
  rules: {
    "nimbus/frontmatter-shape": "error",
    "nimbus/internal-link": "error",
    // 其他规则可按需开启：
    // "nimbus/single-h1": "error",
    // "nimbus/bare-url": "warn",
  },
});
```

`validateMdx` 默认开启，会在构建时检查 MDX 中使用的 PascalCase 组件是否已注册或导入。`false` 可以跳过这项检查。

## Markdown 选项

集成选项中的 `markdown` 控制 Markdown 的处理方式：

```ts title="astro.config.ts"
nimbus(config, {
  markdown: {
    features: {
      // 支持 `## 安装 {#install}` 这样的自定义标题 id
      headingAttributes: true,
      // 开启数学公式
      // math: true,
    },
    hastPlugins: [tableScroll()],
  },
});
```

`features.headingAttributes` 开启后，带有 `{#id}` 的标题会使用固定 id。注意：标题末尾其他 `{…}` 文本，例如 `.md` 文件里的 `{account_id}`，也会被当成属性解析。

## 渲染策略

默认情况下，所有页面都在 `astro build` 时预渲染，产物是纯静态站点。需要按请求渲染页面时，可以设置 `rendering`：

```ts title="astro.config.ts"
rendering: {
  default: "request",
},
```

`"request"` 需要 Astro 的服务端输出适配器（Cloudflare、Netlify、Vercel 或 Node）。如果只想让特定集合按请求渲染，可以在 `rendering.collections` 中按集合名称分别设置。

## 面向智能体

`agents` 控制站点为智能体运行的服务：

| 字段 | 说明 |
|---|---|
| `mcp` | 设为 `true` 后在 `/mcp` 提供远程 MCP 服务器，提供 `list_pages` 与 `get_page`。需要服务端适配器与 `@modelcontextprotocol/server`。默认 `false`。 |
| `discovery` | 设为 `false` 时不在域名根发布发现文件，适合把站点托管在别人拥有的域名下。默认 `true`。 |

```ts title="astro.config.ts"
agents: { mcp: true },
```

更多细节见[面向智能体](/agents/)。完整选项列表请参考 [Nimbus 配置文档](https://nimbus-docs.com/reference/configuration/)。
